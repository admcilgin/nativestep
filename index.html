Installs the nativestep CLI into ~/.nativestep and the skills plugin into Claude Code. macOS or Linux, arm64 or x64. Then run nativestep doctor.

Two ways in, one way of working

A project starts once, from an existing app or from nothing. After that, every project is developed the same way. You ask Claude Code in words or call the skills by name; you make the decisions they hand you.

Tests once, code twice

iOS and Android share no code. They share the behavior contract: one JSON protocol, one set of tests and fixtures. The same test drives every target through the protocol, headless or on a simulator and emulator.

spec/ · written once

Behavior tests in TypeScript (@nativestep/test) and the fixtures that stand in for the network.

Six gates at every checkpoint

Agents work in small checkpoints. Each one passes the gates in order before it is committed, and each result is written to the checkpoint's evidence, where nativestep status reads it.

G0ReferenceTests pass on the Flutter app, or you approve them against the feature doc.
G1BehaviorThe same tests pass on iOS and Android.
G2Lintnativestep lint finds no architecture violation.
G3UI reviewScreenshots match the reference or the design.
G4ArchitectureTwo isolated reviews approve.
G5EngineerYou review the code and the running app.

The mechanical work. Plain text for people, --json for machines.

The skills

The work that needs judgment, as a Claude Code plugin.

step-fixA bug: a red test first, then the fix on both platforms
